Conversation Dynamics

Control how the agent waits and handles interruptions

Instant (0s) Patient (1s)
What it does: How long the agent waits after you stop speaking before it responds. 0s for fastest response, increase to 0.3-0.4s if agent is cutting off users mid-thought.
Dynamic: The agent learns the caller's pause rhythm as the call goes on and adapts how long it waits before replying — quicker for fast back-and-forth talkers, a little more patient for callers who pause mid-thought. This usually feels the most natural and means fewer accidental interruptions, so it's the better choice for everyday conversations. Fixed: The agent always waits the exact Response Delay before replying, every single time. Predictable and consistent — best when you want tightly controlled timing or are troubleshooting an agent — but it can't adjust if a caller speaks faster or slower than expected.
Interruptible (0s) Committed (1.5s)
What it does: How long you must speak to interrupt the agent. 300ms (0.3s) allows quick interruptions while filtering out brief acknowledgments like "uh-huh" or "yes". Lower = easier to interrupt, higher = agent finishes sentences.
Quick (0.5s) Patient (5.0s)
What it does: How long to wait after an interruption before deciding it was false. Higher values give more time to determine if the interruption was real speech or just noise.
Any sound (0) 5 words
What it does: Minimum recognized words before treating user input as a real interruption. Phone agents using Deepgram Flux STT must use 2 or higher — setting to 0 disables protection against false interruptions from echo, breath sounds, or line noise and causes mid-sentence audio cutouts. The runtime auto-floors Flux agents to 2 unless disable_flux_min_words_floor is set.
Disabled (0s) Maximum (10s)
Ignores the caller's audio for this many seconds after the agent's first words, so echo of the agent's own voice can't trigger a false barge-in. Automatic mode adapts this per call type; drag the slider only if a specific line needs a different value. Set to 0 to disable entirely.

Agent Handoffs

Transfers are explicit department handoffs (caller knows). Transitions are silent workflow phase changes (caller doesn't notice).

Not supported on Gemini 3.x: Mid-session agent handoffs require updating the model's instructions during the call, which Gemini 3.x rejects. Any handoffs you configure below will be ignored on this model. Switch to Gemini 2.5 Flash Native Audio (or another realtime provider) to use handoffs.
Tip: Transfers create tools like transfer_to_billing_agent. Transitions create tools like transition_to_scheduling_phase. The LLM decides when to use them based on the descriptions you provide.

How to Use This Agent

Tab Guide:

  • Identity - Agent name, slug, pipeline mode (Standard or Realtime), greeting, system prompt, knowledge base, and tool instructions
  • Behavior - LLM provider/model, temperature, and conversation dynamics (VAD, turn detection, interruption handling, Flux turn detection)
  • Speech Recognition - STT provider, model, language, responsiveness, custom vocabulary, language detection, smart formatting
  • Voice - TTS provider, model/voice, and language selection for speech output
  • Advanced - Resource limits (CPU/memory), agent handoffs (transfer/transition), and data extraction fields

Quick Start:

  1. Configure settings - Use the tabs above to set your agent's identity, behavior, and voice settings
  2. Save the agent - Click "Create Agent" (top-right or bottom of page)
  3. Install dependencies - Go to Settings → Dependencies to install required packages for your chosen providers
  4. Start the agent - Use the Agents page to start/stop the agent worker service

Connecting to This Agent:

  • Phone (SIP) - Configure a SIP trunk and dispatch rule pointing to this agent's slug. Callers dial your SIP number and are routed to this agent.
  • Chatbot - Create a Chatbot Agent to embed an AI chat widget on your website that connects to your LLM.
  • Agent Tester - Use the built-in Agent Tester to test your agent directly from the dashboard with your microphone.
  • Outbound Campaigns - Use Campaigns to have this agent make outbound calls to a list of phone numbers.

How it works: Agent configurations are stored in Redis. The agent worker service automatically loads all configured agents when started. Changes to running agents take effect after restarting the agent service.

                             LLM Fallback & Auto-Failover
                        

                        
                        
Two layers of protection against provider issues: (1) the existing 'Enable LLM Fallback' toggle builds a chain (primary → backup 1 → backup 2) with a per-turn timeout that catches mid-call freezes; (2) the new 'Auto-failover with health checks' toggle periodically probes each provider in the background and auto-routes NEW calls to a healthier backup when the primary degrades. When the primary recovers, the dashboard automatically switches back. A small status line under each provider shows its current state in plain language. Click 'Details' to open the full health modal with a 24-hour latency chart.

                             Turn Detection
                        

                        
                        
Predicts end-of-turn beyond plain silence. Choose Audio (v1-mini) — LiveKit's recommended on-device model that listens to the caller's voice (intonation and pacing), runs entirely on your server with no cloud account, and supports 14 languages — or Text (legacy), the older transcript-based model that LiveKit has deprecated. Off uses silence detection only. Realtime (audio-to-audio) agents can also use Audio (v1-mini): pick it under the Realtime settings' 'End-of-turn detection' option — it automatically turns off the provider's own built-in turn detection so the two don't conflict. AWS Nova Sonic is the exception (it manages turn-taking internally, so the option is shown but disabled there). Note: switching a realtime agent to the on-device detector trades a little extra interrupt latency for smarter end-of-turn that won't cut a caller off mid-thought.

                                        Set to 0.0s to eliminate artificial pauses. Increase to 0.3-0.4s if agent cuts off users.
                                    

                                    
                                    

                                        flux_eot_timeout_ms (EOT Timeout)
                                        Set to 2500ms for faster end-of-turn detection. Maximum wait time before forcing turn end.
                                    

                                    
                                    

                                        Flux Turn Detection
                                        Enable for 39% fewer false interruptions. Set eot_threshold to 0.6-0.7.
                                    

                                    
                                    

                                        resume_false_interruption (Resume After False Interruptions)
                                        When enabled, the agent resumes speaking from where it left off if an interruption turns out to be background noise. Default: On.
                                    

                                    
                                    

                                        false_interruption_timeout (False Interruption Timeout)
                                        How long to wait after an interruption before deciding it was false. Higher values = more patient. Default: 2.0s.
                                    

                                    
                                    

                                        min_interruption_words (Min Words to Interrupt)
                                        Minimum recognized words before treating user input as a real interruption. Phone agents using Deepgram Flux STT must use 2 or higher — setting to 0 disables protection against false interruptions from echo, breath sounds, or line noise and causes mid-sentence audio cutouts. Default: 2 (auto-floored to 2 for Flux agents unless disable_flux_min_words_floor is set).
                                    

                                    
                                    

                                        preemptive_generation (Preemptive Response Generation)
                                        Start generating a response before the user fully finishes speaking. Reduces latency but may occasionally respond too early. Default: On.
                                    

                                    
                                    

                                        prompt_caching_enabled (Prompt Caching)
                                        Shown only for Anthropic direct or Bedrock Claude. Tells Anthropic/AWS to keep a cached copy of the system prompt between calls so subsequent calls respond faster. Default: Off. Do NOT enable with rotating prompts (e.g., AutoResearch A/B variants) — cache writes cost ~25% more than uncached input and may never be read.
                                    

                                    
                                    

                                        flux_skip_response_delay (Flux: Skip Extra Response Delay)
                                        Shown in the Flux panel. When ON (default), the dashboard's Response Delay is bypassed so it doesn't stack on top of Flux's own end-of-turn timeout. Turn OFF only if your TTS is slow on cold start and you want the extra buffer to avoid barge-in.
                                    

                                    
                                    

                                        Agent Warm Idle (Settings > System)
                                        Keeps one agent worker process pre-spawned and preloads the turn-detection model at startup. First call of the day responds ~2-5s faster. Adds ~500MB RAM. Disable on constrained hosts (e.g., 2GB VPS).
                                    

                                    
                                    

                                        System Prompt
                                        Keep concise - fewer tokens = faster LLM response. Move static info to Reference Information.
                                    

                                    
                                
                            

                        

                        
                    

                    
                    

                        

                             Prompt Versioning
                        

                        
                        
Every time you save changes to an agent's system prompt, knowledge base, or tool instructions — whether from the web UI or from an external MCP client — the previous version is automatically saved. You can view version history, compare differences between versions, and restore any previous version.

                        
                        
                        

                            

                                
                                    

                                        Field
                                        Description
                                    

                                
                                
                                    
                                    

                                        Version History
                                        Click the green Versions button to see all saved prompt versions with timestamps and source labels.
                                    

                                    
                                    

                                        Source Labels
                                        manual = browser edit, enrich = Enrich Prompt modal, autoresearch = AutoResearch suggestion accepted, sim test = AutoResearch suggestion saved for a Test-in-Simulation experiment, mcp = API-initiated edit (green badge; shows which API key made the change, useful for audit trails when Claude Code or Cursor edits agents).
                                    

                                    
                                    

                                        Diff View
                                        Click 'Diff' on any version to see a color-coded comparison showing exactly what changed (green = added, red = removed).
                                    

                                    
                                    

                                        Restore
                                        Click 'Restore' to load a previous version into the editor. You must click Update Agent to save the restored version.
                                    

                                    
                                    

                                        Max Versions
                                        Configure how many versions to keep per agent (5-50, default 20). Oldest versions are automatically pruned.
                                    

                                    
                                
                            

                        

                        
                    

                    
                    

                        

                             AutoResearch
                        

                        
                        
AI-powered prompt optimization that analyzes your agent's actual call transcripts to suggest specific improvements. Lives on its own AutoResearch page in the sidebar (Testing section) — the editor's purple AutoResearch button takes you there with the agent pre-selected. Can be run manually or scheduled to run overnight.

                        
                        
                        

                            

                                
                                    

                                        Field
                                        Description
                                    

                                
                                
                                    
                                    

                                        Run Analysis
                                        Select analysis steps, choose an LLM provider/model, set the number of transcripts to analyze (5-50), and click Run Now. Progress is shown step-by-step.
                                    

                                    
                                    

                                        Call Selection
                                        Choose 'Most recent calls' or 'Prioritise problem calls' — the latter hunts for calls that ended in errors, were abandoned, didn't achieve their goal, or had negative sentiment, mixing in a few normal calls for contrast, so the AI learns from what actually went wrong.
                                    

                                    
                                    

                                        Suggestions
                                        Each suggestion shows what would change, which issues it addresses, and a confidence score. Amber warnings flag suggestions that dropped placeholders, shrank suspiciously, or grew too much — review those carefully. Click 'Apply to Live Prompt' to review a side-by-side comparison (editable) and apply — the outgoing prompt is saved to Versions automatically, so applying is always reversible.
                                    

                                    
                                    

                                        Test in Simulation
                                        On voice agents with a test suite, run a suggestion through the suite side-by-side with the current prompt (text-mode, simulated tools — the live agent is untouched) and see the pass-rate comparison before applying. Requires Simulation permissions.
                                    

                                    
                                    

                                        Schedule
                                        Set AutoResearch to run automatically (daily or weekly) at a specific time, including the call-selection mode. Suggestions are never auto-applied — review in Results History.
                                    

                                    
                                    

                                        Reference Calls
                                        Curate your best calls as benchmarks. AutoResearch uses these to score suggestions and ensure they don't make good interactions worse.
                                    

                                    
                                    

                                        Methodology
                                        Advanced: customize the analysis, suggestion, and scoring prompts that drive AutoResearch.
                                    

                                    
                                
                            

                        

                        
                    

                    
                    

                        

                             MCP / API Access
                        

                        
                        
External tools (Claude Code, Cursor, Claude Desktop, scripts) can create, read, update, and delete agents through the built-in MCP server at /mcp. Every field you can edit on this page is also editable over MCP — including the realtime model, voicemail/IVR detection, LLM fallback chain, Azure deployment names, ElevenLabs and Hume voice tuning, knowledge-base assignments, and all conversation dynamics.

                        
                        
                        

                            

                                
                                    

                                        Field
                                        Description
                                    

                                
                                
                                    
                                    

                                        Discovery
                                        Ask your MCP client to call get_agent_config_reference() for the full schema of providers, models, valid values, and nested dict keys.
                                    

                                    
                                    

                                        Creating Agents
                                        create_agent supports standard pipeline (STT → LLM → TTS) out of the box; pass realtime_config to create a realtime audio-to-audio agent.
                                    

                                    
                                    

                                        Editing Agents
                                        update_agent_config takes typed params for common fields (name, system_prompt, llm_*, stt_*, tts_*) plus nested dict params for complex groups: realtime_config, outbound_detection, llm_fallback_config, conversation_dynamics_patch.
                                    

                                    
                                    

                                        Audit Trail
                                        Every MCP edit that touches system_prompt, knowledge_base, or tool_instructions creates a prompt version entry tagged source='mcp' with the API key name — visible in the Versions tab alongside browser edits.
                                    

                                    
                                    

                                        Setup
                                        Enable the MCP server under Settings → Integrations → MCP Server sub-tab (admin only). Generate an API key, optionally restrict by IP. Max 20 keys, 60 requests/min per key. For triggering outbound calls from workflow tools like n8n, use the separate REST API sub-tab instead.
