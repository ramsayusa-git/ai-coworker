A failsafe catches the calls that slip through — a caller hangs up mid-booking, the line drops, the enquiry never gets logged. The wizard sets up BOTH sides for you: a report that sends every finished call to your n8n, and a matching n8n workflow file that emails your team only when a call ended without being handled.

Failsafe (tool check)
Rule-based: emails only when none of your booking/handling tools ran successfully and the caller wasn't transferred. Predictable — recommended when your agent books via a tool.
Failsafe (AI classify)
An AI reads each missed call and decides whether the caller's request was completed before emailing. When in doubt it emails — better a duplicate than a lost lead. Needs an AI credential in n8n.

Finish up in n8n
  1. Import the downloaded file (n8n → Workflows → Import from File).
  2. Attach your SMTP credential to Send Alert Email and Email Error Alert.
  3. Attach your OpenRouter credential to OpenRouter Chat Model.
  4. Activate the workflow (toggle, top right).
  5. Press Send test event below, then check n8n → Executions.
Alerts arrive ~1–2 minutes after a call ends. Until the workflow is imported and activated, this report's history will show failed rows — that's expected. To change recipients later, edit the Config node in n8n. You can re-download this file any time from the report's row.

Automated Reports

Configure email reports that send automatically based on triggers like call completion, AI analysis, or on a daily/weekly schedule.

Report Types
Field Description
Post-Call Summary Sends an email after each call ends with call details, transcription, and cost breakdown
AI Conversation Analysis Sends after AI analysis completes with summary, sentiment, intent, and extracted data
Scheduled Summary Sends a daily or weekly digest with aggregate call statistics and cost breakdown
AutoResearch Complete Sends when an AutoResearch analysis finishes, with the score, issues found, and prompt suggestions
Simulation Complete Sends when a simulation suite run or individual test finishes, with pass/fail results and scores. Covers scheduled tests and crash-interrupted runs; runs you cancel yourself stay silent. Choose whether the rule covers suite runs, individual runs, or both — a test scheduled hourly emails every hour if individual runs are on
Improvement Lab Complete Sends when a Lab replay run finishes or fails, with each variant's word-error-rate results and the winning variant. Failed and interrupted runs email too, so a scheduled overnight run can't die silently — runs you abort yourself stay quiet
Configuration
Field Description
Agent Filter Choose 'All Agents' or select specific voice and/or chatbot agents to report on. Chatbot sessions count as inbound for the Direction Filter
Direction Filter Filter by inbound, outbound, or all call directions
Recipients Email addresses that will receive the report
Email Template Select which email template to use — customise templates in Settings > Email
How It Works

When a call ends or AI analysis completes, the agent worker pushes an event to a Redis queue. The report engine background task polls the queue every 30 seconds, matches events against your report rules, and sends emails to the configured recipients. Scheduled reports check their target time and run when due.

Requirements
Field Description
Email Configuration Email must be configured in Settings > Email (SMTP or AWS SES) before reports can send
Dashboard URL Set the Dashboard Public URL in Settings for links in emails to work correctly
n8n Failsafe Wizard
Field Description
What it does Builds a lost-lead safety net: if a caller hangs up before their booking or enquiry is completed, an n8n workflow emails your team the caller's details for a callback. If the booking/cancellation tool ran successfully, or the caller was transferred to a person, nothing is sent. The wizard creates the report rule (webhook delivery pre-configured) AND a matching n8n workflow file you download and import
Failsafe (tool check) Rule-based: you tick which tools count as 'handled'. Alerts only when none of them completed SUCCESSFULLY — a tool that ran but failed still alerts. Optional AI step extracts the caller's name, spoken number and request from the transcript into the email
Failsafe (AI classify) An AI reads each missed call and decides whether the request was completed before emailing. When in doubt it emails. Needs an OpenRouter credential in n8n
After creating The report is enabled immediately, so history shows failed rows until you import and ACTIVATE the workflow in n8n — that's expected. Alerts arrive ~1-2 minutes after a call ends. Use Send test event on the finish page, then check n8n → Executions
Changing things later Recipients: edit the Config node in n8n directly. Security key: edit the report's API Key, save, re-download (JSON button on the report row) and re-import. Tools/keywords/thresholds: re-run the wizard, then delete the old report and deactivate the old workflow or you'll get duplicate alerts. Don't change the report's webhook field list — the workflow reads exactly those fields
Privacy With AI extraction on, the call transcript is sent to OpenRouter through your own n8n credential. The downloaded file embeds the report's security key — treat it as confidential
