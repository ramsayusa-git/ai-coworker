                        Chatbot Agents
                    

                    
                

                

                    
                    
Create and manage AI-powered chat agents that can be embedded on any website. Each chat agent has its own personality, LLM configuration, and widget appearance.


                    
                    

                        

                             Agent List
                        

                        
                        
Your own software can also drive a chatbot without the widget through the REST API (Settings → Integrations → REST API → Chatbot API card) — see the User Guide, Chatbot Agents → REST API. View all configured chat agents with status (enabled/disabled). Click an agent to edit, or use the Create Agent button. Agents can be toggled on/off, duplicated, exported individually, or deleted. The arrows button (Copy to Voice Agent) makes a phone agent from a chatbot: a preview shows what carries over (prompt, knowledge, tools, memory, language model, speech settings) and what does not (widget look, avatar, SMS, allowed websites, session limits, recording), then the voice agent is created stopped for you to review. It is a one-time copy, not a link. Duplicate now also copies the chatbot's tools and knowledge-base links. Use the Export button to download all agents as JSON, or Import to restore from a previously exported file.

                        
                        
                    

                    
                    

                        

                             Templates
                        

                        
                        
The Templates button opens eight ready-made text chatbots — the same scenarios as the voice agent templates (healthcare clinic, e-commerce support, real estate, hotel concierge, restaurant reservations, IT helpdesk, trades bookings, feedback survey), each adapted for website chat with a complete prompt, reference information, and widget styling. Template chatbots are created ENABLED and answer as soon as the widget is embedded, so the API key shown on the card must be configured first. Templates are text-only; voice can be enabled later in the editor. The Feedback Survey template enables automatic summaries for itself so its answers are captured as extraction fields.

                             Voice tab
                        

                        
                        
Chat Mode (Text / Voice with avatar / Full voice) plus four sub-tabs laid out like the voice-agent editor: Speech Recognition (recogniser, model, language, turn detector, stall recovery, advanced), Voice (provider, model, voice, output volume, markdown filter, advanced), Conversation Dynamics and Recording. The sub-tab you had open is remembered; a save blocked by an invalid value on another sub-tab switches to it. Owns the Chat Mode choice (Text / Voice with avatar / Full voice) and every setting that only matters with sound. Every field shows the value the chatbot already runs with, so opening the tab and saving changes nothing until you edit a field.

                                        Description
                                    

                                
                                
                                    
                                    

                                        Chat Mode
                                        Text (type only), Voice with avatar (agent speaks, visitor types, no mic prompt), Full voice (two-way voice; the browser asks for the microphone).                                         Interruptions
                                        Words needed to cut the agent off, how long the visitor must speak, and false-interruption handling.
                                    

                                    
                                    

                                        Noise cancellation
                                        Full voice only. Server-side cleaning of the visitor's microphone audio (Off / WebRTC APM / DTLN / ai-coustics), echo-canceller warm-up and microphone input rate. Browsers already suppress noise — start with Off. Always off in Voice with avatar (no microphone).
                                    

                                    
                                    

                                        Silence re-engage
                                        Full voice only. When the visitor goes quiet the agent nudges them (ask if still there / repeat / let the AI improvise / custom text) up to a maximum number of times, then says goodbye. Already active on Full voice chatbots; these controls tune it. Always off in Voice with avatar (no microphone, so a reading visitor is never cut off). Inactivity auto-close (Session tab) still ends idle sessions in every mode.
                                    

                                    
                                    

                                        Generation
                                        Pre-emptive generation and speech (faster replies, slightly more usage) and prompt caching for supporting LLM providers.
                                    

                                    
                                    

                                        Record full-voice sessions
                                        Full voice only, off by default. Text and avatar sessions are never recorded. Recordings appear on the chat's page in Chat History (player, download, consent receipt) and on the Recording/Egress page behind 'Include chat sessions'. The transcript is kept either way.
                                    

                                    
                                    

                                        Recording consent
                                        Four settings. Ask first and keep chatting unrecorded if they decline (recommended). Ask first and offer text chat instead. Don't ask and show your notice as a permanent line, recording regardless. Don't ask and show nothing. In the two 'ask' modes nothing is minted and no microphone is requested until the visitor answers. In the two 'don't ask' modes the server decides from this setting and ignores what the browser claims, the consent receipt records that the visitor was never asked rather than pretending they agreed, and the chat layouts show a 'Recording' marker in the header while audio is captured. The Voice Orb and Voice Button display modes render no header, so on 'Don't ask - show nothing' those two show the visitor nothing at all. Recording without consent is unlawful in much of Australia and many other places — that call is the operator's.

                             Voice Mode
                        

                        
                        
Optionally enable voice input so visitors can speak to the agent via microphone. Requires STT and TTS provider configuration. In any voiced mode the agent is automatically given spoken-reply rules on top of your prompt (short replies, no lists or symbols read aloud, natural numbers and dates, one question at a time, typed and spoken messages treated the same) — the transcript still shows every reply as text while it's spoken, and text-only sessions are unaffected.

                        
                        
                        

                            

                                
                                    

                                        Field
                                        Description
                                    

                                
                                
                                    
                                    

                                        Turn Detector
                                        How the agent decides the visitor has finished speaking (voice sessions only). "Audio (v1-mini)" is recommended and the default for new chatbots — it listens to the speech itself, runs on the server at no extra memory cost. "Text model" is the older approach: it needs roughly 1 GB of extra memory for the AI Agent Service, and on smaller servers it is skipped automatically (turn-taking then falls back to simple silence detection). "Off" uses silence detection only.
                                    

                                    
                                    

                                        STT Stall Recovery
                                        If the speech-to-text provider stops responding mid-conversation, the agent recovers missed words, asks the visitor to repeat if needed, reconnects a dead transcription stream, and as a last resort says a goodbye and ends the session. Off by default. Voice sessions only — typed chats are never interrupted by it. You can set how long to wait before recovery starts, and your own goodbye message.
                                    

                                    
                                
                            

                        

                        
                    

                    
                    

                        

                             Virtual Avatar
                        

                        
                        
Render a lip-synced talking-head video of the agent in the chat widget. The avatar provider receives the agent's voice (TTS) and republishes synced audio + video into the room. Voice Mode must be enabled for the avatar to lip-sync to. Seven providers are supported: D-ID (highest quality, slow ~5–15s warm-up, requires a v4 expressive avatar), Tavus (hyper-realistic, requires a Replica + Persona configured for LiveKit transport), Beyond Presence (fastest setup — works with a stock avatar by default), LiveAvatar by HeyGen (dynamic real-time avatars, choose a public avatar or create your own), Anam (lifelike low-latency avatars — pick a stock avatar from the gallery or build a custom one in Anam Lab), Simli (very low-latency real-time faces — pick a Face ID from the default library, optional emotion), and Avatario (720p realtime avatars with an optional custom background image). Spatius is not supported: it renders in the browser with its own SDK, which the chat widget does not load. API keys are configured once on the Settings > Integrations page; per-chatbot avatar selection is on the Avatar tab in each agent's editor.

                        
                        
                        

                            

                                
                                    

                                        Field
                                        Description

Metered from the moment the avatar video appears until hang-up or drop, and shown as an 'Avatar' line in the call's cost breakdown, Chat History and reports. Use a row's Disable toggle (not Delete) to stop billing a provider — deleted default rows are re-created at the next restart.

The Integrations Test button proves the API KEY only — not that the avatar can reach your server.

                                        First message may be delayed 5–15 seconds while the avatar warms up. Subsequent replies are real-time.

Tronic-managed dashboards already meet this.

                             Human Handoff tab
                        

                        
                        
Hand a chat to a person. When the visitor asks for a human (or presses the widget's 'Talk to a person' button), the chatbot says the wait message, stops answering, and sends the conversation to your Webhook URL — usually an n8n workflow that posts to Slack, your CRM or a help desk. Every later visitor message is sent there too. Your team member replies through the reply link the webhook receives (the downloadable n8n workflow includes a reply form) and the reply appears in the visitor's chat, SMS or WhatsApp with their name. When they finish, or go quiet for the set time, the chatbot takes back over and already knows what was said. There is no inbox in the dashboard.

                             SMS / WhatsApp Delivery Channel
                        

                        
                        
Let visitors text (or WhatsApp-message) a phone number and get replies from this same chatbot — same LLM, same system prompt, same knowledge base, same memory. Five providers: Twilio (global), Telnyx (global), Tronic Cloud (Tronic's own gateway at text.tronic.com.au), Sent.dm (one number for BOTH SMS and WhatsApp — replies go back on whichever channel the visitor used), and Custom (n8n) for any other SMS carrier via your own n8n instance. Preset setup is one-time: paste API keys on Settings > Integrations, enable SMS on the chatbot's SMS / WhatsApp tab, pick a provider, type the FROM number (not needed for Sent.dm), and copy the generated webhook URL into your provider's console.

                        
                        
                        

                            

                                
                                    

                                        Field
                                        Description
                                    

                                
                                
                                    
                                    

                                        How it works
                                        An inbound text reaches your dashboard's webhook URL → the chatbot's LLM generates a reply → the provider sends it back as SMS. The visitor doesn't need an app or website — just their phone. Webhook responses go out within ~100ms (the LLM call runs on a background task), so providers don't retry or stall.
                                    

                                    
                                    

                                        Memory per phone number
                                        Each phone number is treated as its own visitor. Mem0 (if enabled) remembers the conversation across SMS sessions for that phone, scoped to this agent. Website widget visitors are kept separate.
                                    

                                    
                                    

                                        Daily reply cap
                                        Per-(agent, phone) cap (default 50/day) prevents Denial-of-Wallet abuse. 0 = unlimited. Drops silently after the limit — the inbound is accepted but no reply is sent (logged in the operator's logs).
                                    

                                    
                                    

                                        Twilio setup
                                        Console > Phone Numbers > your number > Messaging Configuration. Set 'A MESSAGE COMES IN' to Webhook + HTTP POST + paste the URL from this tab. Twilio signs every webhook with HMAC-SHA1; the dashboard verifies it automatically.
                                    

                                    
                                    

                                        Telnyx setup
                                        Mission Control > Messaging > Messaging Profiles > your profile > Inbound Settings. Set Webhook URL to the URL from this tab (HTTP POST), API Version V2 (Ed25519). Paste the Webhook Public Key into Settings > Integrations so the dashboard can verify signatures.
                                    

                                    
                                    

                                        Tronic Cloud setup
                                        Sign in at text.tronic.com.au, open your number's inbound webhook setting, paste the URL from this tab. Two-way SMS requires an AU 10-digit number in international format (e.g. 61400123456) — alpha senders like 'MyShop' are send-only.
                                    

                                    
                                    

                                        Sent.dm setup (SMS + WhatsApp)
                                        Sign in at app.sent.dm, provision your business number, and copy your API key into Settings > Integrations > Sent.dm. In the Sent.dm dashboard create a webhook endpoint pointed at the URL from this tab, subscribe it to message.received, and paste that endpoint's signing secret (whsec_…) into the tab. There is no From number — the sender is the business number on your Sent.dm account, and one Sent.dm number belongs to ONE chatbot (configure exactly one inbound endpoint per account). For WhatsApp, connect your Meta Business account inside Sent.dm (Meta login + payment method on the Meta side). Replies automatically go back on whichever channel the visitor used. Business-initiated sends (test button, voice-agent tool) use a passthrough template the dashboard auto-creates on save. The WhatsApp channel is code-complete but not yet verified end-to-end; SMS is fully tested.
                                    

                                    
                                    

                                        Custom (n8n) setup
                                        Bring any SMS carrier by wiring it through your own n8n instance. Select Custom (n8n), save the chatbot (this generates a shared secret), then download the two ready-made workflows from the SMS tab — they arrive pre-filled with this chatbot's webhook address and secret. Import both into n8n, drop your carrier's node into the Send workflow, activate both, paste the Send workflow's Production URL into the dashboard, and point your carrier's inbound webhook at the Inbound workflow. A Test panel on the tab verifies the setup and can send a real test SMS.
                                    

                                    
                                    

                                        n8n security
                                        Custom (n8n) messages carry an X-SMS-Secret header in both directions, generated by the dashboard (16+ characters, compared in constant time). The secret is baked into the downloaded workflows — if you regenerate it, re-download and re-import BOTH workflows or they stop authenticating.
                                    

                                    
                                    

                                        Webhook security
                                        Twilio + Telnyx use cryptographic webhook signatures (HMAC-SHA1 / Ed25519). Sent.dm signs webhooks HMAC-SHA256 (Svix-style) with a per-endpoint secret you paste into the tab; replayed deliveries are also suppressed. Custom (n8n) uses the shared-secret header. Tronic Cloud has no signature; it relies on your webhook URL staying secret. The agent ID in the URL is opaque, so don't share the URL publicly.
                                    

                                    
                                    

                                        Failure handling
                                        If a key is missing, the provider's API is down, or the LLM call fails, the visitor gets no reply that turn — but nothing crashes. Errors are visible in the operator logs (sms.send.failed / sms.reply.llm_failed).

                             Per-Session Dynamic Variables
                        

                        
                        
Your website can hand the chatbot per-visitor context by adding a data-variables attribute to the embed snippet, e.g. data-variables='{"name": "Priya", "account_number": "1253566"}'. Each key becomes a {{placeholder}} usable in the system prompt and welcome message — "Hello {{name}}, your account {{account_number}} premium is due soon." Rules: variable names are lowercase letters/digits/underscores (max 32 chars), up to 10 variables, values up to 200 characters, ~2KB total. Unsupplied placeholders are removed from the welcome message automatically. IMPORTANT — personalization only, never identity: the token endpoint is public, so any caller can claim any value. The agent must never treat a variable like {{account_number}} as verified identity or feed it to tools as an authenticated lookup key without its own verification step.

                             AutoResearch
                        

                        
                        
AI-powered prompt optimization that analyzes your agent's actual chat session transcripts to suggest specific improvements. Lives on its own AutoResearch page in the sidebar (Testing section) — the editor's purple AutoResearch button takes you there with the agent pre-selected. Can be run manually or scheduled to run overnight.

                        
                        
                        

                            

                                
                                    

                                        Field
                                        Description
                                    

                                
                                
                                    
                                    

                                        Run Analysis
                                        Select analysis steps, choose an LLM provider/model, set the number of chat sessions to analyze (5-50), and click Run Now. Progress is shown step-by-step.
                                    

                                    
                                    

                                        Call Selection
                                        Choose 'Most recent calls' or 'Prioritise problem calls' — the latter hunts for sessions that were abandoned, didn't achieve their goal, had negative sentiment, or where the visitor barely engaged, mixing in normal sessions for contrast.
                                    

                                    
                                    

                                        Suggestions
                                        Each suggestion shows what would change, which issues it addresses, and a confidence score. Amber warnings flag suggestions that dropped placeholders, shrank suspiciously, or grew too much — review those carefully. Click 'Apply to Live Prompt' to review a side-by-side comparison (editable) and apply — the outgoing prompt is saved to Versions automatically, so applying is always reversible.
                                    

                                    
                                    

                                        Schedule
                                        Set AutoResearch to run automatically (daily or weekly) at a specific time, including the call-selection mode. Suggestions are never auto-applied — review in Results History.
                                    

                                    
                                    

                                        Reference Sessions
                                        Curate your best chat sessions as benchmarks. AutoResearch uses these to score suggestions and ensure they don't make good interactions worse.
                                    

                                    
                                    

                                        Methodology
                                        Advanced: customize the analysis, suggestion, and scoring prompts that drive AutoResearch.
