How to Add Tools to Your Agent

Built-in Tools:

  1. Configure global defaults — Click "Configure" on any tool card to set defaults (destinations, SIP trunk, hold music). These are shared by all agents.
  2. Assign to agents — In Agent Tool Assignments above, click "Configure" next to an agent. Toggle tools on/off. Configurable tools show settings below the toggle.
  3. Customize per agent — Override settings for a specific agent (e.g., give one agent only "Debt_Recovery" as a transfer destination). Leave fields empty to use global defaults.
  4. Guide the agent — In the Agent Editor, use Tool Usage Instructions to tell the agent when to use each tool. The system handles correct tool syntax automatically.

Tip: Global settings are defaults — set once, all agents inherit. Per-agent overrides apply to just that agent. Click "Reset to Global" in the agent modal to re-inherit defaults.

Create a Webhook Tool:

  1. Click "+ Create Webhook Tool" in the Webhook Tools section above
  2. Set a name and description — the description helps the LLM decide when to use the tool
  3. Enter your API URL — any HTTP endpoint (n8n, Make.com, Zapier, or custom API)
  4. Add parameters — define what the agent passes to the tool (name, type, description)
  5. Save, then toggle the tool ON for your agent in the Agent Tool Assignments table

Add an MCP Server:

  1. Click "Templates" in the MCP Servers section to choose a pre-configured server, or click "+ Add MCP Server" for custom setup
  2. Provide connection details — URL for SSE/HTTP servers, or command + args for stdio (npx) servers
  3. Add required API keys as environment variables (e.g., BRAVE_API_KEY for Brave Search)
  4. Click "Sync" to connect and discover available tools — they appear in the Tool Registry
  5. Toggle MCP tools ON for your agent in the Agent Tool Assignments table

Tip: Tools are shared across agents — create once, assign to many. Changes take effect after restarting the agent service.

    How Tool Settings Work

    Tools have two levels of settings. <strong>Global settings</strong> (Configure button on the tool card) set defaults shared by all agents. <strong>Per-agent settings</strong> (in the agent assignment modal) let you override settings for a specific agent. Leave per-agent fields empty to use global defaults. In the Agent Editor, use <strong>Tool Usage Instructions</strong> to tell the agent <em>when</em> to use each tool — the system automatically provides the correct tool syntax and available destinations.

    Blind Transfer Destinations — PSTN vs SIP URI

    Each destination on the blind_transfer tool picks one of two types: <strong>PSTN Phone Number</strong> for regular phone numbers (e.g. 61398765432), or <strong>3CX / SIP URI</strong> for direct SIP destinations (e.g. <code>sip:811@your-3cx.example.com</code>). Existing destinations from before this feature have no type set — they're treated as PSTN automatically. The agent's prompt only ever sees the destination <em>names</em>, not the URIs, so renaming a destination propagates without rewriting the system prompt.

    Per-Destination Trunk Override

    Each destination row has an optional <strong>Trunk override</strong> field. Leave it blank to use the tool's default outbound trunk (set above the destinations table). Set a trunk ID here when one destination should dial through a different trunk than the others — e.g. one row uses your PSTN trunk for phone numbers, another uses a 3CX trunk for SIP URIs. The default trunk is still used as a fallback when a row has no override.

    3CX SIP URI Destinations — Setup Requirements

    Transferring to a 3CX queue requires three things on the 3CX side that the dashboard cannot configure remotely: (1) add this dashboard's SIP egress IP as a <strong>Generic SIP Trunk (IP-based)</strong> in 3CX → Voice & Chat → Trunks; (2) whitelist that IP in 3CX → Anti-Hacking; (3) on the trunk, set <strong>Transport: TCP</strong> and turn on <strong>Include diversion header support</strong>. Without all three, 3CX returns SIP 403 Forbidden and the transfer fails. Use a SIP URI of the form <code>sip:&lt;queue-extension&gt;@&lt;your-3cx-fqdn&gt;</code> — the queue extension is shown when you create or edit a queue in 3CX (typically 8xx).

    Transfer Mode — Bridge vs SIP REFER (Advanced)

    <strong>Bridge (default, recommended)</strong> — the dashboard dials the destination directly and bridges the caller into the same audio room. The dashboard knows whether the destination picked up (the SIP "200 OK"), so if they don't answer the agent stays on the call and the LLM can recover ("sorry, they didn't pick up — would you like to try someone else?"). Works on every SIP provider. The dashboard's room stays open during the bridged call, slightly higher resource cost. <br><br><strong>SIP REFER (advanced)</strong> — the dashboard sends a SIP REFER to your upstream provider, which redirects the caller. The dashboard's room ends cleanly (lower resource cost). <strong>You lose the wait-for-answer safety net</strong> — REFER returns success when the gateway acks the message, NOT when the destination actually picks up. If the destination is unreachable, the caller lands on a dead leg with no agent fallback. <br><br><strong>When to pick which:</strong> Twilio Elastic SIP Trunking <em>refuses REFER for non-PSTN URIs</em>, so most customers must stay on Bridge. REFER is the right choice on Telnyx, on REFER-permissive trunks, or when your inbound trunk is your own 3CX server. The setting is per-tool — your upstream trunk determines the right mode.

    n8n Wizard

    The blue 'n8n Wizard' button on the Webhooks tab builds BOTH sides of an n8n integration in one pass: it creates the webhook tool (security key, field names and response handling pre-configured) AND generates a matching n8n workflow file you import — so the two always fit together. The funnel and outbound caller are downloadable recipes — no tool is created; mint the REST API key they need at Settings → Integrations → REST API. After importing in n8n: ACTIVATE the workflow (the test URL only works with the editor open), then replace the red 'REPLACE ME' node with your real action (ready-made recipes have no REPLACE ME node — just fill in their credentials/IDs). Re-download the file any time from the tool card's 'n8n' button — it always reflects the tool's current settings. To rotate the secret: edit the tool, enter a new secret in the Token/Key field, save, then re-download and re-import (delete the old workflow copy in n8n first). Built-in guardrails (on by default, all channels): booking tools refuse to book until an availability check has run in the same call; one-shot actions (book/follow-up/lead/ticket) won't fire twice with identical details — the agent is told it's already handled; and a blank required field doesn't fire the webhook at all — the agent is coached to ask the caller for it first. The blank-field guard is driven by each parameter's Required tickbox — required means enforced, so only mark fields required when the call genuinely can't proceed without them.

    Pre-configured templates for popular MCP servers — Brave Search, Filesystem, Fetch, Qdrant, Supabase, GoHighLevel CRM, and n8n Tools (MCP). Click 'Browse Templates' to set one up quickly — just provide the required keys. GoHighLevel CRM connects agents to your GHL account for contact/conversation/opportunity lookups and updates (needs a Private Integration Token from GHL Settings → Private Integrations plus your Location ID; scope the token to only what agents should touch; note GHL's MCP cannot BOOK appointments — use the n8n Wizard's GoHighLevel card for booking). n8n Tools (MCP) turns one n8n workflow into a whole tool box: download its starter workflow from the template card, import into n8n, add a Bearer credential on the MCP Server trigger, activate, then paste the trigger's Production URL and the bearer token back into the template — every tool you attach in n8n appears after a Sync.

    Syncing MCP Tools

    After adding an MCP server, click 'Sync' to connect and discover its available tools. Synced tools appear in the Tool Registry under the 'mcp' category and can be assigned to agents like any other tool.
