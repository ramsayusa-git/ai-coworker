Overview

AI Voice Agents handle phone calls using three core AI components:

STT (Speech-to-Text)
Converts caller's voice to text
LLM (Language Model)
Understands and generates responses
TTS (Text-to-Speech)
Speaks the response to caller

Conversation Dynamics

These settings control how the agent handles turn-taking, interruptions, and response timing during a call. Found under the Dynamics tab in the agent editor.

SettingWhat It DoesDefaultTip
Timing
Response Delay How long the agent waits after you stop speaking before it responds 0s Increase to 0.3-0.4s if the agent cuts off users mid-thought
Preemptive Generation Start generating a response before the user fully finishes speaking On Reduces latency but may occasionally respond too early
Endpointing Mode Controls how the agent decides when to respond. Dynamic learns caller's pause rhythm; Fixed uses exact Response Delay. Dynamic Use Dynamic for most calls. Switch to Fixed if agent needs precise timing control.
Interruption Controls
Barge-In Threshold How long a caller must speak to interrupt the agent 0.5s Set to 0.3s to allow quick interruptions while filtering brief acknowledgments
Resume After False Interruptions Agent resumes speaking from where it left off if an interruption was background noise On Keep on — prevents the agent from losing its train of thought
False Interruption Timeout How long to wait after an interruption before deciding it was false 2.0s Higher values give more time to determine if speech was real
Min Words to Interrupt Minimum recognized words before treating input as a real interruption 0 Set to 1-2 to prevent coughs or clicks from cutting off the agent
Discard Audio During Announcements Discards buffered caller audio during non-interruptible agent speech On Keep on unless you need to capture what callers say during announcements
Echo Cancel Warmup Ignores the caller's audio for X seconds after the agent's first words, so echo can't trigger a false barge-in Auto (0s outbound, 0.5s inbound phone, 3s web) Leave on Auto; set a manual value only if a specific line has echo issues at call start
User Away Detection Seconds of mutual silence before caller is considered "away" 15s Works alongside End Call on Silence for comprehensive silence handling
Configuration Tips
For Lowest Latency
  • LLM: GPT-4.1 Mini or Gemini 2.5 Flash
  • STT: Deepgram Flux
  • TTS: Cartesia Sonic or ElevenLabs Flash
  • Responsiveness: 0.7-0.9
For Best Quality
  • LLM: GPT-5.2 Instant or Claude Sonnet 5
  • STT: Deepgram Flux
  • TTS: ElevenLabs Turbo v2.5
  • Responsiveness: 0.4-0.6
Dynamic Variables

Use these placeholders in your system prompt, greeting, or voicemail message. They are replaced with real values at call time:

  • {{time_greeting}} (morning/afternoon/evening) — time-of-day greeting based on server time
  • {{user_number}} — caller's phone number (inbound) or dialed number (outbound)
  • {{current_datetime}} — current date and time
  • {{current_date}} — current date
  • {{current_time}} — current time
Quick Tips
  • Health Indicators: Green = ready, Yellow = warning, Red = missing API key or dependency
  • Status: Agents must be "running" to handle calls
  • Edit vs Create: Changes to running agents take effect immediately after restart
  • Logs: Check agent logs for troubleshooting call issues

          Agent Configuration

          Create and configure AI voice agents that handle calls. Each agent has its own personality, voice, and capabilities.

          Agent List

          View all configured agents with status indicator. Click an agent to edit, or use the Create Agent button. Agents can be duplicated, exported, or deleted. The arrows button (Copy to Chatbot Agent) makes a website chatbot from a voice agent: a preview shows what carries over (prompt, knowledge, tools, memory, language model, speech settings) and what does not (phone transfers, voicemail detection, routing slug), then the chatbot is created switched off for you to review. It is a one-time copy, not a link. On Community Edition installs, creation is limited to 2 voice agents and 2 chatbot agents — see the Settings > Licensing tab.

          Templates

          The Templates button (also at Agents → Templates) offers nine ready-made agents: healthcare appointment reminders, a clinic front-desk receptionist (inbound — answers practice questions, collects bookings and messages, triages emergencies to 000, and uses a longer listening pause so hesitant callers aren't cut off), e-commerce support, real estate lead qualification, hotel concierge (speech-to-speech on Grok Voice — needs an xAI API key), restaurant reservations, IT helpdesk, trades job booking, and a customer feedback survey. Each arrives with a complete prompt — including a shared block of phone-call delivery rules for natural-sounding calls — reference information, attached tools (hangup, transfer, date lookup), and settings, then opens in the editor for customisation. Transfer-equipped templates need a destination added under Tools → Blind Transfer before transfers work. The survey and clinic front-desk templates' answers auto-extract only when Auto-generate summaries is on in Settings → AI Summary.

          LLM Fallback & Auto-Failover

          Two layers of protection against provider issues: (1) the existing 'Enable LLM Fallback' toggle builds a chain (primary → backup 1 → backup 2) with a per-turn timeout that catches mid-call freezes; (2) the new 'Auto-failover with health checks' toggle periodically probes each provider in the background and auto-routes NEW calls to a healthier backup when the primary degrades. When the primary recovers, the dashboard automatically switches back. A small status line under each provider shows its current state in plain language. Click 'Details' to open the full health modal with a 24-hour latency chart.

          Field Description
          Enable LLM Fallback Turn on the fallback chain. Required before you can enable auto-failover.
          Fallback Timeout Per-turn timeout used during a live call — if the current provider doesn't respond within this window, the next provider in the chain is tried immediately (default 4 seconds).
          Fallback Provider / Model First backup to try. Ideally a different provider to protect against single-provider outages.
          2nd Fallback Provider / Model Optional second backup. Used only if both the primary and first backup fail.
          Auto-failover with health checks When on, the dashboard runs small background test prompts against each provider at the chosen interval. Poor performance shifts new calls to the first healthy backup; recovery shifts them back automatically.
          Check every How often to probe. Default is 60 minutes. Shorter intervals (10/15/20 min) detect problems faster but cost more in API tokens (cost estimate shown below the dropdown).

          Advanced Speech Settings

          Fine-tune conversation dynamics in the expandable Advanced section. Includes VAD sensitivity, silence thresholds, interruption handling, and Flux turn detection settings.

          Turn Detection

          Predicts end-of-turn beyond plain silence. Choose Audio (v1-mini) — LiveKit's recommended on-device model that listens to the caller's voice (intonation and pacing), runs entirely on your server with no cloud account, and supports 14 languages — or Text (legacy), the older transcript-based model that LiveKit has deprecated. Off uses silence detection only. Realtime (audio-to-audio) agents can also use Audio (v1-mini): pick it under the Realtime settings' 'End-of-turn detection' option — it automatically turns off the provider's own built-in turn detection so the two don't conflict. AWS Nova Sonic is the exception (it manages turn-taking internally, so the option is shown but disabled there). Note: switching a realtime agent to the on-device detector trades a little extra interrupt latency for smarter end-of-turn that won't cut a caller off mid-thought.

          Agent Handoff
          Field Description
          Target Agents Select which agents this agent can hand off calls to
          Handoff Type - Transfer Explicit department handoff. The caller knows they are being transferred to a different agent or department (e.g., 'Let me transfer you to billing').
          Handoff Type - Transition Seamless workflow phase change. The caller does not notice a switch — the conversation continues naturally as if it's the same agent moving to a new topic.
          Sign-off Prompt / Bridge Phrase Transfer: optional announcement before handing off. Transition: optional natural phrase to bridge conversation phases.
          Context Mode Full (complete history), Summary (an AI-written handover brief generated at transfer time — adds a short pause (typically 2-5s, up to 7s on announced transfers); you can pick the model and customise the instructions per target), or Fresh (clean slate for receiving agent)
          Initial Greeting on handoff Announced handoffs speak the target's Initial Greeting as before. On SILENT handoffs the greeting is now the spoken bridge over the changeover: silent transitions speak it by default, silent transfers stay quiet by default, and the per-route 'Speak this agent's Initial Greeting on takeover' tick-box overrides either. A Bridge Phrase on the route is spoken automatically instead and replaces the greeting there. Keep bridge lines to one short phrase - callers cannot interrupt them while the new agent's speech recognition connects.
          Speak greeting on takeover Per-route tick-box. On silent transitions it defaults ON (the greeting covers the changeover gap); untick it on loop-back routes so a call-opening greeting never replays mid-call. On silent transfers it defaults OFF.

          Performance Optimization

          Optimize your agent for faster response times. Target latency: <500ms TTFB (Time To First Byte) for natural conversation, 500-1000ms is acceptable, >1000ms feels broken.

          Field Description
          Fastest STT Deepgram Nova-3 or ElevenLabs Scribe v2 Realtime (~150ms). Set responsiveness to 0.7-0.9 for quicker transcription.
          Fastest TTS ElevenLabs eleven_flash_v2_5 (~75ms latency). Turbo v2.5 (~250ms) for better quality.
          Fastest LLM GPT-4o is 2-3x faster than GPT-4. Use temperature 0.3-0.5 for faster, more deterministic responses.
          vad_threshold (Microphone Sensitivity) Set to 0.35 for faster voice detection. Lower values detect quieter speech but may pick up background noise.
          vad_min_silence (Min Silence Duration) Set to 150ms for quicker turn-taking. How long the agent waits in silence before assuming you've finished speaking.
          agent_response_delay (Response Delay) Set to 0.0s to eliminate artificial pauses. Increase to 0.3-0.4s if agent cuts off users.
          flux_eot_timeout_ms (EOT Timeout) Set to 2500ms for faster end-of-turn detection. Maximum wait time before forcing turn end.
          Flux Turn Detection Enable for 39% fewer false interruptions. Set eot_threshold to 0.6-0.7.
          resume_false_interruption (Resume After False Interruptions) When enabled, the agent resumes speaking from where it left off if an interruption turns out to be background noise. Default: On.
          false_interruption_timeout (False Interruption Timeout) How long to wait after an interruption before deciding it was false. Higher values = more patient. Default: 2.0s.
          min_interruption_words (Min Words to Interrupt) Minimum recognized words before treating user input as a real interruption. Phone agents using Deepgram Flux STT must use 2 or higher — setting to 0 disables protection against false interruptions from echo, breath sounds, or line noise and causes mid-sentence audio cutouts. Default: 2 (auto-floored to 2 for Flux agents unless disable_flux_min_words_floor is set).
          preemptive_generation (Preemptive Response Generation) Start generating a response before the user fully finishes speaking. Reduces latency but may occasionally respond too early. Default: On.
          prompt_caching_enabled (Prompt Caching) Shown only for Anthropic direct or Bedrock Claude. Tells Anthropic/AWS to keep a cached copy of the system prompt between calls so subsequent calls respond faster. Default: Off. Do NOT enable with rotating prompts (e.g., AutoResearch A/B variants) — cache writes cost ~25% more than uncached input and may never be read.
          flux_skip_response_delay (Flux: Skip Extra Response Delay) Shown in the Flux panel. When ON (default), the dashboard's Response Delay is bypassed so it doesn't stack on top of Flux's own end-of-turn timeout. Turn OFF only if your TTS is slow on cold start and you want the extra buffer to avoid barge-in.
          Agent Warm Idle (Settings > System) Keeps one agent worker process pre-spawned and preloads the turn-detection model at startup. First call of the day responds ~2-5s faster. Adds ~500MB RAM. Disable on constrained hosts (e.g., 2GB VPS).
          System Prompt Keep concise - fewer tokens = faster LLM response. Move static info to Reference Information.
          Prompt Versioning

          Every time you save changes to an agent's system prompt, knowledge base, or tool instructions — whether from the web UI or from an external MCP client — the previous version is automatically saved. You can view version history, compare differences between versions, and restore any previous version.

          Field Description
          Version History Click the green Versions button to see all saved prompt versions with timestamps and source labels.
          Source Labels manual = browser edit, enrich = Enrich Prompt modal, autoresearch = AutoResearch suggestion accepted, sim test = AutoResearch suggestion saved for a Test-in-Simulation experiment, mcp = API-initiated edit (green badge; shows which API key made the change, useful for audit trails when Claude Code or Cursor edits agents).
          Diff View Click 'Diff' on any version to see a color-coded comparison showing exactly what changed (green = added, red = removed).
          Restore Click 'Restore' to load a previous version into the editor. You must click Update Agent to save the restored version.
          Max Versions Configure how many versions to keep per agent (5-50, default 20). Oldest versions are automatically pruned.
          AutoResearch

          AI-powered prompt optimization that analyzes your agent's actual call transcripts to suggest specific improvements. Lives on its own AutoResearch page in the sidebar (Testing section) — the editor's purple AutoResearch button takes you there with the agent pre-selected. Can be run manually or scheduled to run overnight.

          Field Description
          Run Analysis Select analysis steps, choose an LLM provider/model, set the number of transcripts to analyze (5-50), and click Run Now. Progress is shown step-by-step.
          Call Selection Choose 'Most recent calls' or 'Prioritise problem calls' — the latter hunts for calls that ended in errors, were abandoned, didn't achieve their goal, or had negative sentiment, mixing in a few normal calls for contrast, so the AI learns from what actually went wrong.
          Suggestions Each suggestion shows what would change, which issues it addresses, and a confidence score. Amber warnings flag suggestions that dropped placeholders, shrank suspiciously, or grew too much — review those carefully. Click 'Apply to Live Prompt' to review a side-by-side comparison (editable) and apply — the outgoing prompt is saved to Versions automatically, so applying is always reversible.
          Test in Simulation On voice agents with a test suite, run a suggestion through the suite side-by-side with the current prompt (text-mode, simulated tools — the live agent is untouched) and see the pass-rate comparison before applying. Requires Simulation permissions.
          Schedule Set AutoResearch to run automatically (daily or weekly) at a specific time, including the call-selection mode. Suggestions are never auto-applied — review in Results History.
          Reference Calls Curate your best calls as benchmarks. AutoResearch uses these to score suggestions and ensure they don't make good interactions worse.
          Methodology Advanced: customize the analysis, suggestion, and scoring prompts that drive AutoResearch.
          MCP / API Access

          External tools (Claude Code, Cursor, Claude Desktop, scripts) can create, read, update, and delete agents through the built-in MCP server at /mcp. Every field you can edit on this page is also editable over MCP — including the realtime model, voicemail/IVR detection, LLM fallback chain, Azure deployment names, ElevenLabs and Hume voice tuning, knowledge-base assignments, and all conversation dynamics.

          Field Description
          Discovery Ask your MCP client to call get_agent_config_reference() for the full schema of providers, models, valid values, and nested dict keys.
          Creating Agents create_agent supports standard pipeline (STT → LLM → TTS) out of the box; pass realtime_config to create a realtime audio-to-audio agent.
          Editing Agents update_agent_config takes typed params for common fields (name, system_prompt, llm_*, stt_*, tts_*) plus nested dict params for complex groups: realtime_config, outbound_detection, llm_fallback_config, conversation_dynamics_patch.
          Audit Trail Every MCP edit that touches system_prompt, knowledge_base, or tool_instructions creates a prompt version entry tagged source='mcp' with the API key name — visible in the Versions tab alongside browser edits.
          Setup Enable the MCP server under Settings → Integrations → MCP Server sub-tab (admin only). Generate an API key, optionally restrict by IP. Max 20 keys, 60 requests/min per key. For triggering outbound calls from workflow tools like n8n, use the separate REST API sub-tab instead.
