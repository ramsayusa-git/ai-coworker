Rules

  • Only the phone number column is required — all others are optional
  • Phone numbers must include the country code (e.g. 1 for US, 61 for Australia) — no + sign needed
  • A header row is optional — the system detects it automatically. If you include one, columns can be in any order as long as names match the table above
  • If there is no header row, columns must be in the exact order shown above (left to right)
  • Leave a column blank (empty value) to skip it — do not remove it if columns after it have data
  • Save your file as .csv (comma-separated) — not .xlsx or .xls

Outbound Campaigns

Create and manage bulk outbound calling campaigns. Campaigns automate dialing lists of phone numbers with your AI agents.

What is a Campaign?

An outbound campaign automatically dials a list of phone numbers using a selected SIP trunk and AI agent. The system handles call pacing, retries, and tracks results for each number. Campaigns work with both PSTN trunks (dialing public phone numbers) and PBX trunks (dialing extensions, queues, or named SIP users on a customer's phone system).

PBX Campaigns

When you select a PBX trunk for a campaign, the CSV's destination column should contain extensions, queues, or SIP user names (e.g. 101, queue302, reception) instead of phone numbers. Full E.164 numbers are also accepted — the PBX decides the routing. Heads up: PBXes throttle total simultaneous calls by license (e.g. 3CX Simultaneous Call units), so the campaign's Concurrent Calls setting must respect that cap or the extra calls will be rejected by the PBX.

Adding Phone Numbers — CSV Import

Upload a .csv file (not .xlsx) to import large lists. The system auto-detects whether the first row is a header. With a header row, columns can be in any order as long as they use the exact names below. Without a header row, columns must appear left to right in this exact order:

Field Description
Column 1 — phone Required. Phone number with country code, no + sign.
Column 2 — name Optional. Contact full name.
Column 3 — company_name Optional. Company name.
Column 4 — company_description Optional. Company description.
Column 5 — job_title Optional. Contact job title.
Column 6 — custom_field_1 Optional. Any custom value.
Column 7 — custom_field_2 Optional. Second custom value.
Dynamic Variables (Personalising Each Call)

Place these placeholders anywhere in your agent's System Prompt. Before each call the agent replaces them with the contact's actual data, so every conversation feels personal.

Field Description
{{Name}} Contact's name (e.g. 'Hi {{Name}}, how are you?')
{{CompanyName}} Company name (e.g. 'I'm calling from {{CompanyName}}')
{{CompanyDescription}} Company description for extra context in the prompt
{{JobTitle}} Contact's job title (e.g. 'As {{JobTitle}} you'll appreciate...')
{{CustomField1}} First custom field — use it for anything: account numbers, dates, products
{{CustomField2}} Second custom field — a second flexible slot
{{user_number}} The phone number being dialled — works for all calls, not just campaigns
{{current_datetime}} Current date and time (e.g. 'Thursday, 20 March 2026 02:30 PM AEDT')
{{current_date}} Current date only (e.g. 'Thursday, 20 March 2026')
{{current_time}} Current time only (e.g. '02:30 PM AEDT')
{{time_greeting}} Time-of-day greeting word — 'morning', 'afternoon', or 'evening' based on the configured timezone

Best Practices

Start with low concurrency (1-2 calls) and increase gradually. Test with a small list first. Schedule campaigns during appropriate calling hours. Monitor the first few calls to ensure your agent handles them correctly.
