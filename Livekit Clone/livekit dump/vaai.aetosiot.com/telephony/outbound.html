Outbound SIP Trunks

Configure SIP trunks for making outgoing phone calls. Required for agents to dial out to phone numbers or to PBX extensions.

Two Trunk Types: PSTN vs PBX

PSTN trunks dial public phone numbers via a SIP carrier (Twilio, Telnyx, Vonage, SignalWire). PBX trunks point at a customer's existing phone system (3CX, Asterisk, FreePBX, Yeastar) and dial internal extensions, queues, or named SIP users (e.g. 101, queue302, reception). Pick the trunk type when you create or edit the trunk.

What is a SIP Trunk?

A SIP trunk connects your LiveKit server to the telephone network (PSTN trunk) or to a customer's PBX (PBX trunk). For PSTN you need an account with a SIP provider; for PBX you need the PBX's address and either an extension's credentials or IP-based whitelisting on the PBX side.

Creating an Outbound Trunk
Field Description
Trunk Type PSTN (default) for public phone network, or PBX for direct dialing into a customer's phone system. Once set, the dashboard adapts every input on this page (number format, caller-ID handling, the test-call form, the campaign CSV behaviour).
Trunk Name Friendly name to identify this trunk in the dashboard (e.g., 'Twilio Production' or 'Joel's Garage 3CX')
Address SIP server hostname or IP address. For PSTN: your provider's address (e.g., sip.twilio.com). For PBX: your PBX's reachable hostname/IP. Include the port (e.g. :5060) to bypass DNS SRV lookup — recommended.
Transport UDP (fast), TCP (reliable; recommended for PBX), or TLS (encrypted; needs explicit :5061 in the address — domain-only TLS is currently broken in livekit-sip).
Number Format PSTN-only. Choose whether phone numbers include the + prefix when sent to your provider. Twilio and most providers require '+E.164 (WITH +)'. Hidden when Trunk Type = PBX.
Numbers PSTN: caller-ID numbers (always WITHOUT the + prefix; the Number Format setting handles the +). PBX (labelled 'Caller-ID to show on transfers'): leave BLANK to forward the original inbound caller's real number on transfers (destination phone shows who's actually calling); type a value to lock the From-URI user-part to that fixed value (e.g. your main DID or 'AIReceptionist').
Username SIP authentication username. PSTN: from your provider. PBX: only required for digest challenge auth — leave blank for IP-based PBX trunks.
Password SIP authentication password (PSTN: from provider; PBX: only with digest auth)
From URI host (PBX, Advanced) Optional. Override the domain in the SIP From header. For 3CX: set to your 3CX SIP domain (3CX Admin → SIP Trunks). For Asterisk: usually the same as the trunk address. Leave blank to inherit the trunk address.
Caller display name (PBX, Advanced) Optional. Caller name shown to the destination phone (e.g. 'AI Receptionist'). Max 128 chars; no line breaks.
Metadata Custom JSON data stored with the trunk for your application logic. Trunk Type and Display Name are managed by the dropdown/Advanced fields above and merged into your metadata on save — do not duplicate them here.
Audio Codecs The format calls travel in. All three are ticked by default and the carrier picks — identical to how trunks have always behaved. PCMU/PCMA are G.711, the standard telephone format nearly every carrier supports. G722 is HD Voice: roughly twice the audio detail, which can improve how accurately the agent understands callers, but many carriers do not offer it.
Only allow the codecs ticked above Forces your selection instead of letting the carrier choose. ⚠️ If the carrier cannot offer one of your ticked codecs it refuses the call with SIP 488 — inbound calls stop arriving and outbound calls stop connecting. Ticking a codec alone does nothing without this box; the list only ADDS to LiveKit's defaults. To undo, tick all three codecs and save. Always make a test call immediately after narrowing.
Media timeout (seconds) Hangs up a call whose audio has stopped flowing, instead of leaving a silent line open. Blank (default) keeps today's behaviour. Minimum 30; 60 is a sensible start. ⚠️ Carriers using silence suppression legitimately stop sending audio while nobody speaks, so a low value can hang up on a quiet caller mid-call. This is not the same as an agent's maximum call duration — that caps a healthy call, this ends a dead one.
PBX Setup — Critical Notes

1) livekit-sip does NOT send SIP REGISTER. Configure your PBX as an IP-based trunk (3CX: 'Do not require — IP Based'; Asterisk pjsip: registration=none with permit=<livekit-sip-IP>). Putting an extension's credentials in Username/Password only authenticates the outgoing INVITE on a digest challenge — it does not register the dashboard as that extension. 2) Codec support: PCMU, PCMA, and G.722 work out of the box. G.729 is NOT supported — if your PBX offers only G.729 the call will fail with 488 Not Acceptable Here. Enable G.711 (µ-law or A-law) on the PBX. 3) Concurrent-call limits: PBXes throttle total simultaneous calls by license (e.g. 3CX Simultaneous Call units, Yeastar channel limits). Campaigns dialing many contacts at once will exhaust these — check your PBX's capacity before running a large campaign.

Number Format Explained (PSTN only)

The Number Format setting determines how phone numbers are formatted when making calls. Your SIP provider expects numbers in a specific format. Twilio requires the + prefix, while some providers work without it. Always enter numbers in the Numbers field WITHOUT the + — the system adds it automatically based on this setting. PBX trunks ignore this setting because the destination is an extension, not a phone number.

Testing Outbound Calls

After creating a trunk, use the 'Create Outbound Call' button to test. PSTN trunks ask for a Phone Number; PBX trunks ask for an Extension or SIP User. Verify caller ID displays correctly and audio works both ways.

Import/Export

Export trunk configurations as JSON for backup. Import to quickly replicate trunks across servers (passwords are not exported for security). Trunk Type, From URI host, and Display Name are included in the export and round-trip cleanly.
