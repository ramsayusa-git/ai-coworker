Inbound SIP Trunks

Configure SIP trunks for receiving incoming phone calls. Required for agents to answer calls from phone numbers.

How Inbound Works

Your SIP provider sends calls to your LiveKit server. The inbound trunk tells LiveKit which providers are allowed to send calls and which numbers to expect.

Creating an Inbound Trunk
Field Description
Trunk Name Friendly name to identify this trunk in the dashboard (e.g., 'Twilio Inbound')
Number Format How incoming caller numbers are received from your provider. Twilio sends numbers WITH the + prefix, so select '+E.164 (WITH +)'. This tells the system what format to expect.
Phone Numbers Phone numbers that will receive calls on this trunk. ALWAYS enter WITHOUT the + prefix (e.g., 61400123123). These are numbers you've purchased from your SIP provider.
Allowed IP Addresses IP addresses allowed to send SIP traffic to this trunk. Restricting IPs is recommended for security - it prevents unauthorized calls. Get these IPs from your SIP provider's documentation. IPs added here are automatically whitelisted in Fail2ban.
Allowed Phone Numbers Only accept calls FROM these caller IDs. Leave empty to allow calls from any number. Useful for restricting who can call in.
Auth Username Username for SIP authentication (optional). If set, incoming calls must authenticate with these credentials instead of IP-based auth.
Auth Password Password for SIP authentication (optional). Used with username for challenge-response authentication.
Metadata Custom JSON data stored with the trunk for your application logic
Audio Codecs The format calls travel in. All three ticked by default and the carrier picks — identical to how trunks have always behaved. PCMU/PCMA are G.711, supported by nearly every carrier. G722 is HD Voice: more audio detail, which can improve recognition accuracy, but many carriers do not offer it.
Only allow the codecs ticked above Forces your selection instead of letting the carrier choose. ⚠️ On an INBOUND trunk the carrier makes the offer, so if it cannot offer one of your ticked codecs the call is rejected with SIP 488 and inbound calls stop arriving. Ticking a codec alone does nothing without this box. To undo, tick all three and save. Test a real inbound call immediately after narrowing.
Media timeout (seconds) Hangs up a call whose audio has stopped flowing. Blank (default) keeps today's behaviour. Minimum 30; 60 is a sensible start. ⚠️ Carriers using silence suppression stop sending audio while nobody speaks, so a low value can hang up on a quiet caller mid-call.
Number Format Explained

The Number Format setting tells the system how your SIP provider sends caller ID numbers. Twilio and most providers send numbers WITH the + prefix (e.g., +61400123123). Select the format that matches your provider. This does NOT affect how you enter numbers in the Phone Numbers field - always enter those WITHOUT the +.

IP vs Credential Authentication

You can secure inbound calls two ways: 1) IP-based: Add your provider's IPs to Allowed Addresses (recommended), or 2) Credential-based: Set Auth Username/Password. If you use credentials, IP restrictions are bypassed and each call must authenticate.

Provider Configuration

Configure your SIP provider to send calls to your LiveKit server's SIP endpoint. The endpoint is typically your-server:5060 for UDP or your-server:5061 for TLS.

Import/Export

Export trunk configurations as JSON for backup. Import to quickly replicate trunks across servers (passwords are not exported for security).
