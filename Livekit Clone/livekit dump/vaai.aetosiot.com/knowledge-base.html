Bulk import memories

Pre-load caller facts in bulk. The agent already looks up memories by phone number at the start of every call — uploaded rows will be injected automatically.

Download template · CSV only, max 10MB, 2,000 facts per upload.
Public Google Sheets only. In Google Sheets click Share (top right) → Change to anyone with the link → Viewer → Copy link, then paste it here. Imports run once — paste the URL again to re-import after edits.
Pinned memories survive end-of-call extraction and FIFO pruning. The agent cannot overwrite or delete them.
CSV format example 
phone_number,Client ID,Plan Tier,Account Balance
+61412345678,CRM-12345,Premium,2500
+61398765432,CRM-67890,Standard,150
First column must be phone_number. Every other column becomes one memory per row in the form Header: value. For the example above, the agent will see facts like Client ID: CRM-12345 and Plan Tier: Premium. Use natural column names — they appear directly in the agent's prompt.
Uploaded data is stored in your configured Qdrant instance and the text of each fact is sent to your configured embedding provider. Each row × column generates one embedding API call.

Knowledge Base

Create and manage knowledge base collections that give your agents access to searchable information using RAG (Retrieval-Augmented Generation).

Overview

The Knowledge Base lets you upload documents and text that agents can search during conversations. When a caller asks a question, the agent automatically searches relevant collections and uses the results to provide accurate answers.

Getting Started

1. Set up Qdrant (Docker or Cloud) using the setup wizard. 2. Configure an embedding provider and model. 3. Create a collection and add documents. 4. Assign the collection to an agent in the agent editor.

Configuration
Field Description
Embedding Provider The AI provider used to convert text into vectors for search. Must be configured in Settings > Integrations first.
Embedding Model The specific model used for embeddings. Different models produce different quality results.
Results per Search How many matching text chunks to return per search query (default: 5).
Chunk Size Size of text chunks in characters. Smaller chunks are more precise, larger chunks provide more context.
Chunk Overlap How much adjacent chunks overlap, to avoid splitting important information across chunk boundaries.
Context Chunks Number of adjacent chunks to include around each search result for additional context. 0 returns only the matched chunk.
Score Threshold Minimum similarity score (0-1) for search results. Results below this threshold are discarded. Lower values return more results, higher values return only the most relevant.
AI Answer Synthesis When enabled, search results are passed through an LLM to synthesize a concise answer before returning to the agent. This produces more natural responses but adds latency and LLM cost.
Synthesis Provider The LLM provider used for answer synthesis. Leave as 'Use AI Summary default' to use the provider configured in Settings > Integrations.
Synthesis Model The specific model used for answer synthesis. Leave as 'Default' to use the model configured in Settings > Integrations.
Synthesis Prompt The system prompt used when synthesizing answers from search results. Customize this to control how the LLM formats and filters knowledge base results.
Collections

Collections group related documents together. Create separate collections for different topics (e.g., 'Product Info', 'Company Policies'). Each collection uses the same embedding model configured above.

Documents

Add documents to a collection by pasting text or uploading files. Supported file formats: TXT, MD, CSV, and PDF (max 10MB). PDF files are automatically processed with text extraction. Documents are split into chunks and embedded for vector search. You can view, download, add, or delete documents within each collection.

URL Sources

Add web page URLs, Google Docs, or Google Sheets as knowledge sources. Content is automatically fetched, extracted, and indexed into the collection. Configure auto-refresh intervals (1 hour, 6 hours, 12 hours, 24 hours, 7 days, or 30 days) to keep content up to date — the system will automatically re-fetch and re-index the URL content on the configured schedule.

Assigning to Agents

In the agent editor (Identity tab), select which collections an agent can search. An agent can access multiple collections. The agent will automatically search assigned collections when it needs information to answer questions.

Agent Memories (mem0)

The Agent Memories section at the bottom of this page lets you browse and manage per-agent conversational memory powered by mem0. When memory is enabled on an agent (via the Memory tab in the agent editor), the agent remembers facts from past conversations and recalls them automatically when the same person calls back or chats again. Voice calls are indexed by the caller's phone number. Web chats are indexed by a persistent browser ID. You can view all memories per agent, filter by user (phone number or visitor ID), delete individual memories, clear all memories for an agent, or use the 'Forget User' button to delete all memories for a specific phone number across all agents (GDPR/privacy compliance). Requirements: mem0ai package (install from Settings > Dependencies) and Qdrant running.
