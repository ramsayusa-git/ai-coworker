Call History

View and analyze past calls with AI-powered summaries, transcriptions, sentiment analysis, and comprehensive latency monitoring.

Call List

Browse all past calls with filtering by date range, agent, direction (inbound/outbound), and status. Use checkboxes for bulk delete operations.

Bulk Operations

Select multiple calls using checkboxes, then use 'Delete Selected' to remove them. 'Select All' selects all visible calls on the current page.

Possible STT Stall Warning

Calls where the caller was heard speaking but speech-to-text produced no transcription are flagged with an orange warning triangle in the call list and a notice on the call detail page. This usually indicates the speech-to-text provider silently stalled mid-call. If the agent's STT Recovery option is off, the notice links to the agent editor so you can enable automatic recovery. The detection threshold adapts to each agent's configuration; setting STT_TRANSCRIPTION_TIMEOUT_S=0 in the server's .env file disables the diagnostic entirely (calls already flagged keep their historical warning).

Latency Metrics Card

Collapsible section showing comprehensive latency analytics. Expand to see overall stats, component breakdown, and per-agent performance. Data loads on expansion.

Latency Overview Stats
Field Description
Avg TTFB Average Time-To-First-Byte across all calls - how long until agent starts speaking
P50 50th percentile (median) latency - half of calls are faster than this
P90 90th percentile latency - 90% of calls are faster than this
P99 99th percentile latency - identifies worst-case outliers
Component Breakdown Chart

Doughnut chart showing how latency is distributed across components: STT (speech-to-text, green), LLM (language model thinking time, blue), and TTS (text-to-speech, orange).

Latency Trend Chart

Line chart showing P50 and P90 latency by hour. Helps identify patterns like increased latency during peak hours. Filter by 24h, 7 days, or 30 days.

Per-Agent Latency Table

Compare latency performance across different agents. Shows average TTFB, P50, P90, and sample count per agent. Lower numbers are better.

Slow Calls Warning

Alert shown when calls with latency >1000ms are detected. Target: <500ms for natural conversation, 500-1000ms is noticeable, >1000ms feels broken.

Call Details - Latency Breakdown

Each call's detail page shows a visual component bar with STT/LLM/TTS proportions, percentile metrics, and turn count for that specific call.

SIP Codec

For SIP trunk calls, the call detail page shows the negotiated audio codec (e.g., G.711 µ-law, G.711 A-law, G.722 HD). This is the codec used between LiveKit and the SIP trunk provider.

AI Call Summary

AI-generated analysis including conversation summary, key topics discussed, sentiment analysis, action items, and call outcome classification.

Sentiment Journey

Visual sparkline chart showing caller emotional journey throughout the call. Tracks sentiment changes from start to end with trend indicator (improving/stable/declining).

Interruption Analysis

Estimates speaking overlaps between user and agent. Shows 'User interrupted AI' vs 'AI interrupted User' counts. Warning displayed for high interruption rates.

Transcriptions

Full call transcript with speaker labels, timestamps, and per-segment sentiment coloring. Expandable/collapsible for long calls.

Tool Calls in Transcription

When an agent uses tools during a call (hangup, transfer, get_datetime, etc.), they appear inline in the transcription with purple styling. Shows tool name, arguments passed, and result returned.

Call Audio Processing (Settings > Storage)

How the server processes the caller's voice during calls. Three options: <strong>24 kHz — standard</strong> (how the system always worked; installs upgraded from earlier versions stay here until changed, while new installs start on 16 kHz for all agents), <strong>16 kHz for all agents</strong> (lighter on the server for phone calls — phone lines carry narrow-band audio, so callers hear no difference; AI providers that need 24 kHz are detected automatically and keep it), or <strong>Choose per agent</strong> (adds an 'Audio Processing Rate' choice to each voice agent's editor under Speech Recognition > Audio Input Settings; agents without their own choice — including chatbot and realtime agents — follow the server default). Changes apply from the next call, no restart needed.

History Retention (Settings > Storage)

Everything is kept forever by default — nothing is deleted unless you set a period. Three independent controls: <strong>Call History</strong> (voice call records + transcripts, fixed rule: X days after the call), <strong>Chat History</strong> (chatbot conversations + widget messages + SMS threads under one sliding rule: X days after the last message, plus an optional max-messages-per-conversation cap), and <strong>Recording Storage</strong> (audio files, X days after recording). Each has a separate 'on this server' and 'in the cloud (S3/GCS)' setting — cloud deletion is permanent, asks for confirmation, and never touches backups or diagnostics data. Widget messages and SMS always live on the server (never in cloud storage). Each section also has a <strong>Daily clean-up time</strong> (default 3:00 AM) deciding when its daily deletion run happens, in the time zone set in Settings > Time &amp; Date; if the dashboard was off over that time, the run catches up shortly after it comes back. Saving a deletion rule still cleans up immediately as well. Widget/SMS messages are exact-expiry and ignore the clean-up time. API note: retention_days 0 in /api/call-history/backup/config means 'keep forever'.
